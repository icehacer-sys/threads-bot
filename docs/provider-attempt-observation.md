# Reply-client provider observation

The coverage log's `replyProvider` object contains cumulative, memory-only **reply-client process** counters. The other coverage fields describe one poll. Their time scopes differ; do not divide them into a coverage or success rate.

`transport.starts` counts invocations of the Anthropic SDK client's fetch function. It includes SDK retries, recursive draft repairs and forced-tool continuations. It does not establish that the provider received or billed a request, accepted a draft or published a reply. One completed classifier invocation can involve several transport attempts, or none for a direct guard. SDK retry ordinals and HTTP statuses use fixed buckets. The SDK retains its existing retries, backoff, timeouts, request parameters and error handling.

`usage.records` counts projections made after the existing spend-record calls. These are successful parsed SDK responses, including responses later rejected by validation. Each token/cache/search field has a `reportedTotal`, `knownRecords` and `unknownRecords`. When a field has never been reported, its total is `null`; a reported zero stays zero. Totals with unknown records are partial. Failed requests and failed JSON parsing do not create usage records; their billing remains unknown. Server-side searches are reported usage and are not extra client HTTP attempts.

Installation failure falls back to the SDK's default fetch and reports unavailable transport counters (`null`). Observation failures are caught and counted without exposing raw error text; rejected observer promises are not awaited. Counters use fixed memory and saturate at the safe integer limit, with `measurement.saturated` marking incomplete totals. Diagnostics never read or clone response bodies and retain no authorization headers, URLs, request bodies, prompts, comments, drafts or media.

This slice supplies no per-comment attribution, logical call identifiers or repair/continuation labels. It leaves the coverage ledger's drafting stages untouched. Separate preflight, learning and token-count clients are outside this scope. It provides no durable history, account-wide spending reconciliation or provider quality comparison, and changes no publication or spending decision.

Run `npm run provider:verify` with `NODE_OPTIONS=--import=./tools/offline-guard.mjs` in a checkout without environment files. The existing hosted coverage checks include this command. Synthetic fixtures compare the actual SDK/classifier with observation seams removed and inject observer, installation and usage failures. They preserve full requests, decisions, returned errors, spending, logs and caller completion counts. Fixture short backoffs are accelerated; this is not a proof of live latency or provider billing.
