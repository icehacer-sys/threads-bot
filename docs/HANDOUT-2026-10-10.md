## 3. Reply bot: how it works now

- **Provider:** `BOT_REPLY_PROVIDER=deepseek` in `.github/workflows/reply.yml`. DeepSeek drafts
  everything. Claude is used only for web lookups (`reference` category) and as fallback when
  DeepSeek fails. Rollback = set it to `claude` (or `hybrid`); takes effect at the next handoff.
- **Breaker:** a DeepSeek failure costs a flat $0.35 once, Claude answers, DeepSeek is off for the
  process and `state.deepSeekHalt` keeps it off for the cap-day.
- **Budget:** `BOT_DAILY_USD=1.60`, `BOT_ESCALATE_USD=1.12`, medical reserve in between. Order must
  hold: escalate < (daily − reserve) < daily. `npm run budget:verify` checks it.
  Cap-day runs **12:00 → 12:00 Cairo**, not midnight.
- **Caps:** 250/day (Threads ceiling), per-post caps, 3 turns per person per thread.
- **Pre-reveal hold:** every comment on a case post is held until the answer is public, then answered.
  So the first 20 min after posting are silent by design. Never hint or confirm a guess before reveal.
- **Accuracy:** the bot only uses case facts (`whatYouSee` / `whyItMatters` / `treatment` from the
  publisher's read-only bridge). DeepSeek-only guards in `src/reply.ts` / `src/deepseek-media-policy.ts`
  refuse unsupported side (laterality) claims, invented pack claims, drug jokes, case-facts meta talk.
- **Concerns:** image/anatomy concerns get one neutral acknowledgment and a review hold that pauses
  image-dependent replies on that post. `npm run reviews` lists them; owner resolves.
- **Safety:** no personal medical advice, no diagnosing, no public accuracy fights, never claim the
  image is a real unedited patient film (they are AI recreations of real conditions).
- **Promo:** product links only when someone explicitly asks where to buy; 1/post, 2/day.
- **Bot GIF replies are OFF** (owner wants text only). Reading commenter GIFs stays ON.
- **Voice learning:** `voicelearn.yml` daily, writes `data/voice-learned.md` (capped ~16 bullets).
- **Code-level tic guards** in `index.ts` (`throttleLaugh`, `stripTics`, `dedupeStamp`) exist because
  prose rules were ignored. Do not remove them as "redundant".

## 5. Owner rules that apply everywhere

- **No commas** in public content and replies, except genuine 3+ item lists. Blank-line spacing.
- Answers keep the sections What you see / Why it matters / Treatment (PDFs also need Treatment).
- **Never** add an "AI-generated" tag.
- **Voice north star:** a witty real person reacting to *this specific* comment. Generic, safe,
  templated, or whiffed-joke replies are the failure. Humanness over hedging.
- **Case bar:** "what the hell is that" in 1 second. Visceral abdomen/pelvis/skull, the body grew it,
  one everyday-object analogy, self-minimized symptom in the hook. Score with the 10-point checklist
  (see memory `case-shock-checklist.md`). Pick deliberately with `--diagnosis`.
- **No dental cases** (owner is medical, not dental). Systemic diseases with jaw findings are OK.
- gpt-image cannot render "absence"/displacement findings (vanishing bone, deviated trachea,
  ankylosis). Prefer bold additive/expansile findings.
- Follower count (~348K) is **bot-inflated**. Only viewer metrics are real. North star = gross follows
  per 100K non-follower viewers.

## 6. Hard-won operational gotchas

- **Never run `npm run live` locally.** The Actions worker is the only publisher; a local run double-posts.
- **Catch-up after a missed night:** cancel the in-progress run *first*, `git pull --ff-only`, edit
  `state.json`, push, then `gh workflow run reply.yml -f mode=live -f window=<START-END>`. A post is
  invisible to the bot 16h after it goes up. Zero the spend record after a daytime catch-up.
- **Don't edit `state.json`** holds/skips/receipts/checkpoints except with an owner-approved command.
  Never reset corrupt state to empty.
- **xray-cases:** never stage `data/usage.jsonl`; after any push check
  `gh run list --workflow publish.yml --limit 2` shows a run `in_progress`, else dispatch one.
- A per-call instruction in `reply.ts` beats the cached system prompt, so any `e.g.` example in code
  must match `voice.ts` (`npm run voice:verify` enforces this).
- Threads caps posts/replies at **500 chars**. Images to Anthropic must be **base64**, not URL.
- Owner pays the bills: never change billing limits, buy anything, or post publicly without asking.
